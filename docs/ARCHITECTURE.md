# Архитектура

Браузер → публичный Caddy HTTP → gateway → landing / workspace / admin / Python API.
Локальный запуск обращается к gateway напрямую на localhost.
API → PostgreSQL (учётные записи, декларации, профиль, аудит).
API → Redis/RQ → worker → ядро агента и провайдеры OCR/LLM.
API и worker → persistent documents volume.
knowledge-sync → разрешённые публичные URLs → архив снимков, без активации правил.

## Границы ответственности

- Ядро агента поставляется Python-пакетом из отдельного Git-подмодуля `agent/`.
  Оно извлекает содержимое документов, формирует поля, проверяет цитаты и
  возвращает уточняющие вопросы. API и worker используют один закреплённый коммит пакета.
- Backend передаёт ядру документы, параметры анализа и функции вызова моделей.
  Backend управляет очередью, настройками провайдеров, историей запусков и записью ответов.
- Frontend не хранит ключи моделей, не рассчитывает таможенные платежи и не принимает
  решение о юридической полноте декларации.
- Backend авторизует каждую операцию. Админка — отдельная сборка, но доступ
  обеспечивается серверными проверками ролей, а не скрытием кнопок.
- Анализ работает в отдельном процессе. Запуск сохраняет профиль и зашифрованный
  снимок нужных ключей; по завершении/ошибке снимок ключей уничтожается.
- В запросах к модели документы явно помечены как недоверенные данные;
  модель не имеет инструментов для выполнения инструкций из документов.
- Все модельные сведения остаются предложениями до проверки. Ссылка проверяется
  на наличие цитаты в извлечённом тексте, а не на смысловое следование.
- Контекст содержит факты, выводы, неизвестное и конфликты. Неподтверждённый
  «факт» понижается до предположения. Добавление/удаление документа очищает старый контекст.
- Повторный анализ сохраняет ручные поля. Изменения имеют аудит before/after.
- Выпуски анализа сохраняют результат для последующего сравнения.

## Хранение и запуск

Postgres и Redis не публикуют порты. Порт gateway привязан к loopback.
Отдельный Compose-проект Caddy публикует порт 80. HTTPS отключён по решению владельца.
Cookie HttpOnly/SameSite=Strict; COOKIE_SECURE=false для HTTP-прототипа,
проверка Origin у изменяющих запросов, Argon2-пароли, Fernet-ключи провайдеров.
ENCRYPTION_KEY должен сохраняться вместе с резервными копиями, иначе ключи API
невозможно расшифровать. .env и данные не включаются в Git и Docker build context.

Первая версия создаёт схему через SQLAlchemy create_all. Перед первым изменением
схемы уже используемой базы необходимо добавить миграцию; create_all не мигрирует столбцы.
Обновление базовой схемы не должно выполняться удалением volume.

## Конвейер декларации

Целевой файл — XML для импорта в Альта-ГТД. Официальный XML электронной ДТ
по XSD ЕАЭС — другой адаптер и в этот выпуск не входит.
Работа приложения заканчивается формированием, проверкой и выдачей готового XML.
Пользователь самостоятельно импортирует файл в Альта-ГТД. Интеграция с программой,
управление её интерфейсом и выполнение импорта агентом в задачу не входят.

1. Реестр обработчиков читает текст, таблицы, вложенные изображения и архивы.
   OCR получает только растровые страницы/изображения и кэшируется по содержимому
   и профилю. PDFium работает на вызывающем потоке; параллелятся HTTP-запросы OCR.
2. Агент извлечения возвращает типизированные наблюдения с документом, координатой
   и цитатой. В больших XLSX модель задаёт схему столбцов, код читает все строки;
   неоднозначные строки остаются в модельном пути. Каталог не является списком поставки.
   Языковые копии таблиц в одной книге сопоставляются по последовательности артикулов
   и количеств. Короткая таблица может полностью совпасть с началом длинной: дополнительные
   строки сохраняются. Все цитаты обеих копий остаются, разные значения дают конфликт.
   Итоги каждой таблицы инвойса читаются алгоритмически, включая несколько счетов
   на одном листе. Повторное извлечение на границе порций PDF объединяется только
   при совпадении уникального цитируемого участка исходной страницы.
3. Реестр поставки опирается на строки фактических коммерческих инвойсов.
   Роли документов отделяют проформы, налоговые счета-фактуры, упаковочные листы,
   технические справки и иностранные декларации. В смешанных Excel-книгах роль
   отдельной таблицы инвойса сохраняется. Копии с подтверждёнными номерами инвойсов
   связываются построчно, повторные физические строки одного инвойса не удаляются.
   Полная исходная таблица может определять состав копии с тем же номером и итогом,
   если сумма всех её строк точно соответствует явно подписанным итогам инвойса.
   Отличающиеся итоги не позволяют автоматически исключить другую редакцию.
   Упаковочные и технические документы дополняют строки по артикулу и количеству;
   ограниченный модельный поиск может присоединить сведения к одной строке инвойса,
   но не объединить несколько его товаров. Если основных строк не больше 80,
   большие наборы вспомогательных документов обрабатываются порциями с тем же
   набором основных строк; вызов ограничен 160 сущностями. Большие реестры требуют
   дальнейшего сопоставления кандидатов; несопоставленные строки остаются в аудите.
   Доставка отдельной строкой сохраняется как расход и входит в сумму инвойса,
   но не создаёт товар. Распределение расходов требует подтверждённого основания.
   Иностранная экспортная ДТ не задаёт направление и валюту российской декларации.
   Перед сопоставлением отдельный вызов предлагает исключение предыдущих редакций
   и документов иных сделок. Замена требует цитат из обеих редакций; исходные
   наблюдения сохраняются, решение и причина видны в отчёте. Неоднозначность
   не разрешается принудительным выбором последнего по дате файла.
4. Отдельный специалист составляет реестр действительно представленных документов.
   Упоминание договора в инвойсе не доказывает наличие файла договора.
5. Нормативный агент формирует поисковые гипотезы, инструмент FTS5 возвращает
   выдержки, другой вызов проверяет проект. URL, хэш, версия снимка и точная цитата
   сохраняются. Кандидаты кодов из номенклатуры остаются предложениями.
6. Алгоритмы объединяют реквизиты, выявляют конфликты, проверяют обязательные
   компоненты, числа и вес. Decimal-инструменты расчёта требуют явных ставок;
   автоматического выбора ставки/льготы и заполнения платежей пока нет.
7. Версионированный адаптер сериализует поддержанные поля в AltaGTD. Несопоставленные,
   некорректные и конфликтные значения перечисляются в отчёте и не экспортируются.

Это ограниченный граф специалистов, а не свободный цикл вызовов модели. На этапах
выдаются только нужные данные и JSON-схемы; модель не выполняет код, не изменяет
правила, не открывает произвольные ссылки и не перезаписывает ручные значения.
Повторная попытка исправления JSON ограничена; профиль и фактическая модель записываются.
При переполнении ответа извлечение пробует компактные товарные строки с одной
цитатой на строку, затем уменьшает порцию. Это применяется и при прерванном/некорректном
ответе; глубина повторного дробления ограничена. Сбой нормативного специалиста
помечает соответствующую порцию как непроверенную и сохраняет извлечённые сведения.

## Модели и исправления

Исходная конфигурация — `deepseek-flash` через официальный DeepSeek API для всех
ролей; на 14.11.2026 это публичный ID указанной пользователем V4.1 Flash 1017.
Распознавание требует vision, извлечение — структурированного JSON, сопоставление
и нормативная проверка допускают отдельную reasoning-модель. Настройки токенов
и режима thinking задаются по роли. Отсутствующая модель роли наследует извлечение.
Реестр документов использует модель извлечения.

Дополнительная модель не обязательна: поиск сейчас работает локально на SQLite FTS5.
При росте базы можно подключить multilingual embedding и reranker через отдельные
адаптеры поиска. Они не заменяют проверку применимости нормы и цитат. Локальный OCR
можно подключить через существующий callback; это отдельный способ снизить стоимость.

Правка графы создаёт `Correction` со старым/новым значением, цитатой, клиентом,
причиной и автором. Администратор утверждает либо отклоняет пример. При следующем
анализе используются только подходящие утверждённые примеры того же клиента.
Неподтверждённые исправления не влияют на другие дела. JSONL-экспорт готовит
материал для отдельного обучения весов; задача обучения у провайдера не запускается.
Таблица добавляется через create_all без изменения существующих таблиц/столбцов.

## Нормативные источники

Сохраняются все шесть пользовательских ссылок Альта, порядок заполнения №257,
ссылка на формат №75 и официальный раздел ЕЭК с PDF групп ТН ВЭД, тарифами и ОПИ.
Обновление выполняет отдельный `knowledge-sync`; анализ декларации, поиск и чтение
сохранённой редакции не обращаются к сайтам. Краулер не вызывает LLM.

`crawler.py` ведёт в SQLite постоянную очередь найденных URL и журнал проходов.
Обход ограничен исходными источниками, главами **и статьями** Кодекса, группами
тарифа и PDF ЕЭК; произвольные ссылки и внешние перенаправления не загружаются.
По умолчанию: 250 документов за проход, глубина 2, до 5000 найденных URL,
8 МБ на документ. Незавершённая очередь продолжается после перезапуска.
Старые JSON-кэши импортируются при обнаружении соответствующей страницы.

Проверяются robots.txt (Protego), Crawl-delay и Request-rate, выдерживается пауза
минимум 1 секунду на хост. Недоступный robots.txt приостанавливает обход; разрешение
не предполагается. HTTP 403/429/5xx и Retry-After сохраняют паузу хоста между
проходами. `--force` не отменяет эти ограничения. Обход защиты сайтов отсутствует.
Редиректы документов разрешены только внутри того же источника и хоста;
редирект robots.txt сейчас считается недоступностью и требует настройки адаптера.

ETag/Last-Modified позволяют получить 304 без повторной передачи документа.
SHA-256 фиксирует редакцию; исходные байты, извлечённый текст, поисковые фрагменты,
ссылка на предыдущий снимок и число изменённых строк сохраняются локально.
Сбой загрузки/разбора не удаляет прежний снимок и не обновляет дату его успешной
проверки. Файлы записываются атомарно, параллельный запуск краулера блокируется.

Поиск FTS5 выбирает редакцию до поиска по тексту. При `as_of=YYYY-MM-DD`
приоритет у редакции с подтверждённым периодом действия. Пересекающиеся периоды
помечаются как конфликт, отсутствие подходящей редакции — как неподтверждённая
применимость. Дата загрузки никогда не используется как дата вступления в силу.
Сейчас автоматического определения/утверждения периодов и полного движка
действия нормативных актов во времени нет. Новые снимки имеют `pending_review`.
Выбор даты доступен в поиске базы; агент пока не передаёт дату оформления в поиск.

`GET /api/knowledge/status` показывает известные URL, индексированные документы,
редакции, задержки обновления, ошибки и последний проход. Счётчики не доказывают
полноту нормативной базы. `GET /api/knowledge/snapshots/{id}` читает архив локально.
Оба маршрута требуют авторизации. В «Базе знаний» доступны состояние и чтение
сохранённой редакции; в результатах анализа видны проблемы обновления.

Настройки сервиса в Compose: `KNOWLEDGE_INTERVAL_SECONDS=86400` (повторная
проверка URL), `KNOWLEDGE_POLL_SECONDS=300` (продолжение очереди),
`KNOWLEDGE_BATCH_SIZE=250`, `KNOWLEDGE_REQUEST_DELAY=1.0`.
`python -m app.knowledge --status` показывает состояние без сети,
`python -m app.knowledge` выполняет один проход, `--watch` продолжает работу.

Дальнейшее наполнение: адаптеры официальных публикаций законов, изменений,
классификационных решений и разрешительных требований; утверждение редакций
и периодов; структурированные ставки/льготы отдельно от поиска по тексту.
Пока это архив ограниченного набора источников, не полная правовая система.

## Воспроизводимая проверка

Один каталог на комплект. Первичные документы и клиентские архивы читаются отдельно;
`GTD_*.xml` открывается **только после** формирования результата для сравнения,
`*.GTD.ZIP` не используется. Значения эталонов не передаются моделям.

```bash
backend/.venv/bin/python scripts/extract-declaration-cases.py \
  --input /path/to/cases --output .local/declaration-eval \
  --key-file /path/to/private-key-file
backend/.venv/bin/python scripts/evaluate-declarations.py \
  --cache .local/declaration-eval --expected /path/to/cases \
  --output .local/declaration-eval/results --key-file /path/to/private-key-file
python3 scripts/report-declarations.py .local/declaration-eval/results
```

Первичное наполнение и фоновые обновления базы выполняются отдельно
(`python -m app.knowledge` в настроенном backend либо
`knowledge.sync(Path(cache_dir))` для отдельного прогона). Перед каждым анализом
повторная загрузка источников не нужна.
Кэш извлечения нужно удалить при изменении обработчика/модели, если требуется
новый OCR. Кэш ответов анализа учитывает профиль и точный текст запроса.

Для каждого комплекта сохраняются XML, наблюдения, реестр документов, вопросы,
нормативные ссылки, список входов и журнал вызовов. Сравнение покрывает все непустые
XML-листья и атрибуты с сохранением повторных узлов; дополнительно — восемь общих
реквизитов, число товаров, мультимножество кодов и суммы весов/стоимостей.
Поэлементное сравнение зависит от порядка товаров; суммы и коды — нет.
Регистрационные и служебные поля эталона также видны в разнице, но не должны
копироваться в новый проект. Это не проверка юридической корректности.
Повторный прогон может использовать кэш извлечения и неизменённых модельных запросов;
журнал различает новые API-вызовы и попадания в кэш. Отчёт до/после:
`python3 scripts/report-declarations.py /path/to/new --baseline /path/to/baseline`.
Флаг оценщика `--ledger-only` сохраняет диагностический реестр до дорогой нормативной
проверки. Такой запуск не создаёт XML, не читает эталон и не считается полным тестом.

## Что остаётся до итоговой декларации

- Проверка соответствия XML формату импорта Альта-ГТД и расширение адаптера на все
  необходимые реквизиты (включая типы документов графы 44 и платежи).
- Выбор актуальных редакций коммерческих документов и юридическая группировка
  товарных строк в товары ДТ с контролем сумм и количеств.
- Даты действия норм, классификаторы, тарифы, льготы и разрешительные требования.
- Проверка каждого полного комплекта декларантом. `review` означает проект,
  а не готовность к подаче. Импорт итогового файла выполняет пользователь вне приложения.

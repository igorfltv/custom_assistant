# Форма

Рабочее пространство специалистов по таможенному оформлению.
Одна компания, 150–300 деклараций в месяц, импорт в РФ.

## Репозитории и границы

| Каталог | Репозиторий | Назначение |
|---|---|---|
| корень | `igorfltv/custom_assistant` | Оркестрация, deploy, общие UI-примитивы, документация |
| backend | `igorfltv/custom_assistant-backend` | Python API, документы, очередь, модели, проверки |
| landing | `igorfltv/custom_assistant-landing` | Публичный сайт |
| workspace | `igorfltv/custom_assistant-workspace` | Кабинет специалиста |
| admin | `igorfltv/custom_assistant-admin` | Настройки, сотрудники, статистика |

Компоненты закреплены git submodules. `packages/ui` — общая дизайн-система,
HTTP-клиент и оболочка; бизнес-функции остаются в приложениях. Приложения
собираются в отдельные образы. Все запросы браузера идут через один origin.

## Локальный запуск

Требуются Docker с Compose, Python 3 и доступ к приватным репозиториям.

```bash
git clone --recurse-submodules https://github.com/igorfltv/custom_assistant.git
cd custom_assistant
./scripts/deploy-local.sh
```

Скрипт создаёт секреты один раз, сохраняет существующую конфигурацию и данные,
собирает образы, запускает сервисы и проверяет HTTP endpoints.

- Сайт: http://localhost:18761/
- Кабинет: http://localhost:18761/workspace/
- Админка: http://localhost:18761/admin/
- Начальный email/пароль: `.local/admin-credentials.txt` (0600).

Ключи провайдеров добавляются в админке. Сначала сохраните ключ, получите список
моделей, выберите точный ID для OCR и анализа и сохраните профиль.
Реальные вызовы платных API выполняются только после запуска анализа пользователем.

Для другого локального порта задайте `APP_PORT` перед первым запуском либо
согласованно измените `APP_PORT` и `PUBLIC_ORIGIN` в `.env`.

## Возможности прототипа

- Авторизация, роли, приглашение сотрудника по email через одноразовую ссылку.
- Загрузка PDF, DOCX, XLSX, XLS, PNG/JPEG/TIFF, удаление и получение оригинала.
- OCR выбранной vision-моделью, текст и таблицы из файлов, сопоставление данных через LLM.
- Контекст поставки: товар, маршрут, участники, условия, документы и неизвестное.
- Источники значений, маркировка неподтверждённых цитат и конфликтов.
- Каталог 54 граф, товарные позиции, ручные изменения и повторный анализ.
- Отдельные провайдеры/модели OCR и анализа, зашифрованные ключи,
  фиксированный профиль каждого запуска и история вызовов.
- Фоновое архивирование восьми нормативных страниц раз в сутки;
  новые снимки ожидают проверки и не становятся действующими правилами автоматически.
- Рабочий JSON-экспорт, статистика фактических обработок и возвращённых API расходов.

## Границы текущей версии

**Это прототип, а не готовый генератор таможенных деклараций.**
XML-экспорт возвращает 409 до согласования XSD, реализации маппинга и проверки
на эталонных комплектах. Автоматического импорта в Альту нет и не планируется:
итоговый XML скачивает специалист и загружает вручную.

Каталог 54 граф не заменяет полную схему электронного документа. Пока реализованы
базовые проверки наличия, кода и веса; отраслевые условия, тарифы, платежи и
все требования по товарам ещё не реализованы. Статус `review` никогда не означает
готовность к подаче. Классификация по ТН ВЭД не выполняется без подтверждённых правил.

Контекст и извлечённые факты требуют проверки: совпадение цитаты доказывает наличие
текста в документе, но не правильность интерпретации моделью. Изображения в старом
XLS следует приложить отдельно; DOC нужно предварительно сохранить в DOCX.
Лимиты прототипа: 30 МБ/файл, 50 файлов/комплект, 120 страниц/файл,
180000 символов входного контекста. Превышение вызывает явную ошибку без обрезания.

Приглашения не отправляют email: администратор передаёт ссылку сотруднику.
Стоимость отображается только если API её вернул; прочие вызовы учитываются отдельно.

## Проверка

```bash
cd backend && uv sync --frozen && uv run --frozen pytest -q
cd .. && npm ci && npm run build
./scripts/deploy-local.sh
```

Тесты используют синтетические документы и заглушки моделей. Реальное качество
провайдеров и юридическая полнота требуют отдельных проверок на материалах компании.

См. [план](docs/PLAN.md), [развёртывание](docs/DEPLOYMENT.md) и [архитектуру](docs/ARCHITECTURE.md).

# Форма

Рабочее пространство специалистов по таможенному оформлению.
Одна компания, 150–300 деклараций в месяц, импорт и экспорт.

## Репозитории и границы

| Каталог | Репозиторий | Назначение |
|---|---|---|
| корень | `igorfltv/custom_assistant` | Оркестрация, deploy, общие UI-примитивы, документация |
| backend | `igorfltv/custom_assistant-backend` | Python API, хранение, очередь, подключение провайдеров |
| agent | `igorfltv/custom_assistant-agent` | Извлечение текста, анализ документов, проверки, уточняющие вопросы и архив нормативных источников |
| landing | `igorfltv/custom_assistant-landing` | Публичный сайт |
| workspace | `igorfltv/custom_assistant-workspace` | Кабинет специалиста |
| admin | `igorfltv/custom_assistant-admin` | Настройки, сотрудники, статистика |

Компоненты закреплены git submodules. `packages/ui` — общая дизайн-система,
HTTP-клиент и оболочка; бизнес-функции остаются в приложениях. Приложения
собираются в отдельные образы. Все запросы браузера идут через один origin.

## Локальный запуск

Требуются Docker с Compose, Python 3 и доступ к приватным репозиториям.

```bash
git clone --recurse-submodules https://github.com/igorfltv/custom_assistant.git
cd custom_assistant
./scripts/deploy-local.sh
```

Скрипт создаёт секреты один раз, сохраняет существующую конфигурацию и данные,
собирает образы, запускает сервисы и проверяет HTTP endpoints.

- Сайт: http://localhost:18761/
- Кабинет: http://localhost:18761/workspace/
- Админка: http://localhost:18761/admin/
- Начальный email/пароль: `.local/admin-credentials.txt` (0600).

Ключи провайдеров добавляются в админке. Сначала сохраните ключ, получите список
моделей, выберите точный ID для OCR и анализа и сохраните профиль.
Реальные вызовы платных API выполняются только после запуска анализа пользователем.

Для другого локального порта задайте `APP_PORT` перед первым запуском либо
согласованно измените `APP_PORT` и `PUBLIC_ORIGIN` в `.env`.

## Серверный прототип

- Сайт: http://89.232.170.118/
- Кабинет: http://89.232.170.118/workspace/
- Админка: http://89.232.170.118/admin/

Прототип публикуется по HTTP, без HTTPS, по решению владельца.
SSH-туннель для этих адресов не нужен. Публичный Caddy-прокси слушает порт 80;
backend, БД и Redis не публикуют отдельные внешние порты.
В Cloud.ru нужно разрешить входящий TCP 80 для публичного интерфейса ВМ.
После первого `scripts/deploy-remote.sh` запустите `scripts/enable-public-access.sh`.
См. [инструкцию](docs/DEPLOYMENT.md).

## Возможности прототипа

- Авторизация, роли, приглашение сотрудника по email через одноразовую ссылку.
- Загрузка PDF, DOC/DOCX, XLS/XLSX, изображений, текста, CSV/TSV, XML/JSON,
  клиентских ZIP/7z и MP4/MOV. Готовые декларации и GTD.ZIP исключаются из входа.
- Реестр обработчиков, OCR с кэшем, координаты таблиц и изображений,
  извлечение по частям без усечения текста. Большие таблицы читаются по схеме столбцов.
- Отдельные этапы извлечения, сопоставления товаров, реестра документов,
  поиска норм и проверки с проверяемыми цитатами.
- Контекст поставки: товар, маршрут, участники, условия, документы и неизвестное.
- Источники значений, маркировка неподтверждённых цитат и конфликтов.
- Каталог 54 граф, товарные позиции, ручные изменения и повторный анализ.
- Отдельные провайдеры/модели OCR, извлечения, сопоставления и проверки, зашифрованные ключи,
  фиксированный профиль каждого запуска и история вызовов.
- Фоновое архивирование нормативных источников Альта и официальных PDF ЕЭК,
  полнотекстовый поиск по версиям, проверка обновлений раз в сутки;
  новые снимки ожидают проверки и не становятся действующими правилами автоматически.
- Статистика фактических обработок и возвращённых API расходов.
- XML-проект для ручного импорта в Альта-ГТД и отчёт об исключённых реквизитах.
- Подтверждённые исправления: поиск примеров того же клиента и JSONL для обучения.

## Границы текущей версии

**Это прототип, а не готовый генератор таможенных деклараций.**
`GET /api/declarations/{id}/export.xml?draft=true` выдаёт XML-проект в структуре
AltaGTD. Это формат импорта в программу, не электронная ДТ по XSD ФТС/ЕАЭС.
Конфликтные, некорректные и неподдерживаемые реквизиты пропускаются с отчётом.
Финальная выгрузка без `draft=true` возвращает 409: соответствие полному формату
импорта и юридическая полнота пока не подтверждены. Целевой результат — готовый
к импорту XML; импорт в Альта-ГТД пользователь выполняет самостоятельно.
Интеграция для загрузки файла в Альту в задачу не входит.

Каталог 54 граф не заменяет полную схему электронного документа. Пока реализованы
базовые проверки наличия, кода и веса; отраслевые условия, тарифы, платежи и
все требования по товарам ещё не реализованы. Статус `review` никогда не означает
готовность к подаче. Классификация предлагает кандидатов по цитатам номенклатуры;
редакция нормы и применимость на дату не утверждаются автоматически.

Контекст и извлечённые факты требуют проверки: совпадение цитаты доказывает наличие
текста в документе, но не правильность интерпретации моделью. Изображения в старом
XLS/DOC следует приложить отдельно. Из видео читаются шесть кадров без звука.
Лимиты: 30 МБ/загрузка, 50 загрузок/комплект, 500 страниц/файл,
3 млн символов извлечённого текста/загрузка; архив — до 500 файлов и 500 МБ
на уровень, два уровня вложенности. Превышение вызывает явную ошибку без усечения.
Таблицы `corrections`, `company_profiles`, `shipment_settings` создаются аддитивно; существующие столбцы не меняются.

Приглашения не отправляют email: администратор передаёт ссылку сотруднику.
Стоимость отображается только если API её вернул; прочие вызовы учитываются отдельно.

## Проверка

```bash
uv run --directory agent --locked pytest -q
uv run --directory backend --locked pytest -q
npm ci && npm run build
./scripts/deploy-local.sh
```

Автотесты используют синтетические документы и заглушки моделей. Для реальных
комплектов доступны `scripts/extract-declaration-cases.py` и
`scripts/evaluate-declarations.py`; команды и ограничения — в
[архитектуре](docs/ARCHITECTURE.md). Приватные входы, ключи и результаты хранятся
в игнорируемой `.local/`, не в Git.

См. [план](docs/PLAN.md), [развёртывание](docs/DEPLOYMENT.md) и [архитектуру](docs/ARCHITECTURE.md).

Постоянные реквизиты задаются в админке → «Компании». В карточке декларации кнопка
«Параметры поставки» выбирает профиль и задаёт дату, процедуру, таможенные органы
и стоимость. Поставка хранит версию профиля; обновление компании не меняет старые
поставки. После изменения параметров требуется повторный анализ. Противоречия
с документами требуют явного разрешения в черновике и пропускаются при XML-экспорте.
